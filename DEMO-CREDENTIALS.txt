3. CÁC KỊCH BẢN DEMO BẮT BUỘC (THEO YÊU CẦU BUỔI 15)

   [Kịch bản 1: Happy Path - Luồng chuẩn thành công]
   - B1: Đăng nhập tài khoản `seller_demo` qua POST /api/auth/login.
   - B2: Đăng sản phẩm mới (POST /api/products) với CategoryId = 1 hoặc 2.
   - B3: Đăng nhập `bidder_demo` và `bidder_demo2`, cùng đặt giá tăng dần (POST /api/products/{id}/bids).
   - B4: Worker tự động mở phiên và đóng phiên sau thời gian kết thúc.
   - B5: Xem Order vừa được tạo tự động cho người thắng (GET /api/orders/me).
   - B6: Xem Thông báo nhận được trong hệ thống (GET /api/notifications/me).

   [Kịch bản 2: Luồng dữ liệu sai & Bắt lỗi nghiệp vụ (Validation & Edge cases)]
   - Lỗi 400 (bid_too_low)       : Đặt giá thấp hơn giá khởi điểm hoặc sai bước giá.
   - Lỗi 403 (seller_cannot_bid) : Người bán tự lấy token của mình đi đặt giá sản phẩm của chính mình.
   - Lỗi 409 (auction_closed)    : Cố tình đặt giá khi phiên chưa bắt đầu hoặc đã kết thúc.
   - Lỗi 409 (concurrency)       : Hai người đặt cùng một mức giá hoặc xung đột phiên bản RowVersion.

   [Kịch bản 3: Phân quyền Authorization (RBAC - User gọi API Admin)]
   - Dùng token của `bidder_demo` (Role: User) gọi:
     + POST /api/categories (Tạo danh mục)  --> Server chặn 403 Forbidden!
     + PATCH /api/admin/users/1/status     --> Server chặn 403 Forbidden!
   - Đổi sang token của `admin` (Role: Admin) gọi lại --> Server cho phép 200 OK.
   - Admin khóa tài khoản User: User đó gọi bất kỳ API nào sau đó đều bị chặn 403 ngay lập tức dù Token JWT chưa hết hạn (nhờ cơ chế CurrentUser.RequireActiveAsync kiểm tra DB).
